OPERATING PROCEDURE
1. Resolve `PROMPT_TAG` to one prompt file under `prompts/`.
2. Read the current prompt completely.
3. Determine the prompt's real task domain, deliverable, and operating environment from its file path and content.
4. Read `CRITIQUE_TEXT` closely and extract the smallest set of underlying failure modes that explain the observed problems.
5. For each failure mode, identify the most likely cause in the current prompt, such as:
   - missing priority order;
   - vague task boundaries;
   - weak failure behavior;
   - overbroad inputs;
   - missing verification;
   - contradictory incentives;
   - buried or optional hard constraints;
   - structural boilerplate that crowds out execution logic.
6. Separate essentials from accidents:
   - preserve the underlying user goal;
   - preserve any genuinely effective repository constraints;
   - discard wording, sections, and habits that are not pulling their weight.
7. Design the replacement prompt before drafting:
   - define the minimum input set;
   - define the target agent role;
   - define the core priorities;
   - define the non-negotiable rules;
   - define the step-by-step workflow;
   - define the validation checklist;
   - define failure behavior;
   - define the completion deliverable.
8. Only after that design pass, write the new prompt from scratch. Do not edit the old prompt line by line.
9. While drafting, prefer consolidation over accretion:
   - replace several narrow exception rules with one stronger governing rule when possible;
   - move important decisions earlier in the prompt;
   - turn fuzzy intentions into observable checks;
   - remove generic filler that does not change runtime behavior.
10. If the target prompt's domain implies repository authorities or style guides, inspect the relevant local files and reference only the ones the executing agent truly needs.
11. Overwrite the original prompt file with the completed rewrite.
12. Before finishing, run the validation checklist below.
